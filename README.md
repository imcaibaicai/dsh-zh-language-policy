# dsh-zh-language-policy

[English](README.en.md) | 简体中文

DSH 语言契约插件（宿主侧，可装卸）：在**每轮模型步骤之前**重新把两条契约插到系统提示词最顶部——「英文思维链 + 简体中文可见正文」与「最终总结必须自包含」。纯插件实现，不改核心、不动官方任何文件。

## 它解决什么问题

1. **语言漂移**：DeepSeek 系模型在读完大段英文工具输出后，可见正文容易被带成英文；用户在对话里直接读到英文散文。
2. **总结漏事实**：界面默认把一个回合的中间过程行折叠在最终总结后面，用户主要读总结；过程中看到的重要信息若没写进总结，就等于丢了。

## 实现机制（有源码依据，非拍脑袋）

harness 通过 `ctx.systemPrompt.section()` 按 `order` 组装系统提示词；harness 身份段在 -100、部署 persona 在 0。本插件把两条契约锚在 **-200 / -190**，即所有其它指令之前；且组装在**每个模型步骤前**重跑，契约每轮都被重新断言——这正是「英文工具结果之后也拉得回来」的解药。

两条契约都是简短的正面表述（设定预期行为，而不是跟模型斗），中英双语（模型在它所治理的语言里读到每条规则）：

1. **语言契约**（order -200）：内部推理/思维链用英文；面向用户的一切可见文字（回答、总结、步骤叙述、解释）必须简体中文；技术词保持原文但用中文句子包住；每次写可见文字前自查，拿不准就写中文。
2. **总结完整性契约**（order -190）：回合结束界面自动折叠中间过程行，用户主要读最终总结，所以总结必须自包含——复述要求与实际动作、包含所有重要结果/数字/决定及理由/失败与下一步、用行内代码列出创建或修改的文件路径、过程中用户看到过的任何重要信息都要进总结。

完整双语契约原文见 `lib/index.js` 的 `CONTRACT` 与 `SUMMARY_CONTRACT`。

## 安装

```bash
dsh plugin --profile web add -w dsh-zh-language-policy
```

宿主插件在 DSH 启动时加载，**装完必须完全退出并重启 DeepSeek Harness**。

## 卸载

删 `cordis.patch.yml` 里的 `zh-language-policy` 插入行 + 删包目录，重启即可。

## 兼容性与版本敏感性

- 测试于 DeepSeek Harness `0.1.5-rc.1`（web profile，宿主侧）。
- **注意**：契约的 `order` 锚点（-200 / -190）相对 harness 内部常量（身份段 -100、persona 0）。DSH 升级后若这些内部常量发生变化，需要在 `lib/index.js` 里同步调整 order 值，否则契约可能不再位于提示词最顶部。升级 DSH 后建议先读一遍官方 `dsh-system-prompt` 的 section order 再重启。

## 与社区同类插件的差异

市场里有强制「思维链也中文」的语言类插件；本插件明确**保留英文思维链**（用户看不到、保持英文即可），只强制可见正文中文，并把「总结完整性」与折叠特性绑定——这是两个不同的治理目标。
